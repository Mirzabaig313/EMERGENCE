# Grayscale Sprite Design Guide

This guide documents the process, best practices, and technical constraints for creating new grayscale block art creature sprites for EMERGENCE. Use this reference when contributing new sprites to the `sprites_grayscale` library.

---

## 1. Design Goals

- **Classic Roguelike Aesthetic**: Emulate ASCII/block art styles from classic dungeon crawlers (NetHack, Angband, Dwarf Fortress).
- **Grayscale Only**: Use the provided grayscale Unicode block palette to ensure consistent lighting and shading.
- **Readable Silhouettes**: Creatures must be recognizable at a glance using a clear profile silhouette.
- **Animation Ready**: Maintain consistent anchor points and proportions across the four core animation states (idle, attack, damaged, death).
- **Performance Friendly**: Keep sprites optimized for rendering in terminal environments (max width 45 chars, max height 25 lines).

---

## 2. Palette & Character Set

Use the following Unicode block characters exclusively for shading and detail:

```
█ = Full block (100% solid)
▓ = Dark shade (75%)
▒ = Medium shade (50%)
░ = Light shade (25%)
  = Background / transparent

▀ = Upper half block           ▄ = Lower half block
▌ = Left half block            ▐ = Right half block

■ = Small filled square        □ = Small empty square
▪ = Tiny filled square         ▫ = Tiny empty square
```

### Palette Rules
- **Black Background**: Use spaces to represent negative space. Do not render background shading.
- **Light Source**: Assume light source from top-left. Highlights should use `░`, mid-tones `▒`, shadows `▓`, and cores `█`.
- **Half Blocks**: Use `▀` and `▄` to soften top/bottom edges. Use `▌` and `▐` for left/right edge refinement.

### Anchor Points
- `anchor_x`, `anchor_y` indicate the contact point with the ground (bottom center).
- When designing, ensure feet/grounded limbs align with consistent anchor positions across states.

## 4. Creation Workflow

1. **Silhouette Sketch**
   - Start with `█` blocks to define the creature’s profile at idle.
   - Focus on major shapes: head, torso, limbs, appendages.

2. **Volume & Shading**
   - Establish light direction (top-left).
   - Use `▓` for shadowed surfaces, `▒` for mid-tones, `░` for highlights.
   - Avoid overusing `░`; reserve for specular or high-contrast areas.

3. **Texture & Detail**
   - Reptile scales: pattern alternations (`▓▒` grids).
   - Fur: dither with `░▒` combos.
   - Bone: sharp contrasts with `█` edges and `░` highlights.
   - Armor: alternating checkerboard of `█` and `▓` to mimic metallic sheen.

4. **Animation States**
   - **Idle**: Neutral stance; primary silhouette reference.
   - **Attack**: Increased motion, extended limbs/weapons, dynamic pose.
   - **Damaged**: Recoil or stagger. Shift weight backward/up.
   - **Death**: Collapsed silhouette. Ensure lower profile, maintain readability.

5. **Directional Consistency**
   - All base sprites face right.
   - Left-facing versions are generated by `sprite_flipper.flip_sprite_horizontal`.
   - Validate flipped results for directional characters (`▌` ↔ `▐`, `/` ↔ `\`).

6. **Validation**
   - Check width/height constraints for all states.
   - Render in terminal using `GrayscaleSpriteRenderer` gallery or sprite sheet builder.
   - Verify readability at default terminal font size (80×24, 100×30).

---

## 5. Repository Integration

### Sprite Data (`sprites_grayscale.py`)
- Define constants for each state (e.g., `DRAGON_IDLE_RIGHT`).
- Register in `CREATURE_SPRITES` with metadata (`width`, `height`, `anchor`, `tier`, `category`).
- Ensure string arrays use consistent indentation (no trailing spaces).

### Raw Assets (`assets/creatures_grayscale.txt`)
- Update the raw art file using the provided generation script or manual insertion.
- Include all states for each creature.

### Manifest (`assets/sprite_manifest.json`)
- Add entry under `creatures` with metadata.
- Update `tier` lists and `total_sprites` count if new creatures/states are added.

### Documentation
- Update `GRAYSCALE_SPRITES.md` with previews and metadata.
- Mention new creatures in relevant sections and changelog.

## 6. Shading Techniques

### Depth & Volume Example
```
    ░░░
   ░▒▒▒░
  ░▒▓▓▓▒░
  ░▒▓█▓▒░
   ░▒▒▒░
    ░░░
```

### Texture Patterns
- **Scales** (`▓▒` alternating):
  ```
  ▓▒▓▒▓
  ▒▓▒▓▒
  ▓▒▓▒▓
  ```
- **Fur** (`░▒` dithering):
  ```
  ░▒░▒░
  ▒░▒░▒
  ░▒░▒░
  ```
- **Bone** (high contrast):
  ```
  █▓▒░
  ▓▒░
  ▒░
  ░
  ```
- **Armor** (checkerboard):
  ```
  █▓█▓█
  ▓█▓█▓
  █▓█▓█
  ```

## 7. Quality Checklist

Before submitting a new sprite:

- [ ] Silhouette is readable and iconic.
- [ ] Shading reflects top-left light source.
- [ ] Width ≤ 50, height ≤ 25.
- [ ] Anchor positions consistent across states.
- [ ] Attack pose shows clear action.
- [ ] Damaged pose shows clear recoil.
- [ ] Death pose collapses convincingly.
- [ ] `sprite_flipper` produces correct left-facing version.
- [ ] Added to manifest, docs, and raw asset file.
- [ ] Rendered and validated using the renderer gallery.

## 9. Collaboration Notes

- Use branches per feature (e.g., `feat-new-sprite-<name>`).
- Follow existing code formatting (4-space indentation, uppercase constants).
- Avoid trailing whitespace in sprite lines.
- Include descriptive commit messages referencing added creatures/states.
- Coordinate tier/category assignments with design leads.
